2HTML / 마크업

  • 진행 방식: 디자인셀이 정적 HTML·SCSS·UI JS까지 만들고 → 개발팀이 이 마크업을 받아 서버 템플릿에 붙이는 분업. 그래서 "개발자가 그대로 가져다 쓸 수 있는 마크업"이 목표
  • 한 파일에 전체 화면: main.html(3,969줄) 안에 header + 지도 main + 서비스별 aside 4개 + 모달. 어떤 aside를 보일지는 클래스(is-active)로만 제어
  • data 속성으로 동작 연결: data-modal-open="service-select" ↔ data-modal, data-slide="project-area-1", data-aside, data-action="download-report" → 개발자는 JS를 몰라도 속성만 맞추면 열기·전환이 됨
  • 상태는 클래스로 통일: is-open / is-active / is-expanded / is-disabled / is-downloading, 스텝은 complete / active. 주석에 상태 값을 적어 둠 (<!-- STEP 1: complete(완료), active(진행중), 없음(미진행) -->)
  • 섹션 주석 규칙: <!-- 섹션명 시작 --> / <!-- //섹션명 끝 --> 중첩 구조까지 일관 적용 (3,969줄 파일에서 개발자가 위치를 찾기 쉽게)
  • 접근성: 아이콘 버튼에 .sr-only 텍스트 21곳, aria-label 15곳, 로고 영역 role="button" tabindex="0", type="button" 명시, lang="ko"
  • 보안 meta: Content-Security-Policy, X-Content-Type-Options: nosniff, Referrer-Policy
  • 인라인 style은 15곳 — 슬라이드 폭(width: 398px, CSS 주석에 "inline style로 덮어쓰기 가능"이라고 명시)과 면적 바 비율(width: 14%, 개발 단에서 값 주입)처럼 데이터로 바뀌는 값에 한정
  • 네이밍: 케밥케이스 + 블록 접두어(sidebar-slide-header, area-stats-legend-item). SCSS에서 &-header로 중첩해 블록 단위로 관리

주요 인터랙션

  • 모달: openModal / closeModal / closeAllModals (요소 또는 data 값 둘 다 받음). 닫기 버튼·오버레이 클릭·ESC 키로 닫기, 열릴 때 body overflow: hidden으로 배경 스크롤 잠금, 다른 모달이 남아 있으면 잠금 유지
  • 서비스 전환: 카드 선택 → 모든 슬라이드 닫기 → 모든 aside 숨김 → 해당 aside 활성화 → 모달 닫기 → aside 애니메이션 후 첫 슬라이드 열기 (setTimeout)
  • 슬라이드 토글 버튼 위치: sidebar-default.offsetWidth + slide.offsetWidth로 left 계산 → 패널 폭이 달라져도 버튼이 가장자리에 붙음
  • 아코디언(항목선택 카테고리): scrollHeight로 실제 높이를 재서 max-height 지정 → CSS 트랜지션으로 부드럽게 열림. 탭 전환 시 숨겨졌던 항목 높이 재계산
  • 세그먼트 탭, 페이지네이션(이전/다음, 현재/전체 표시, 끝에서 버튼 비활성), 신청목록 펼침 행·하위 메뉴 행 토글, 검색창 X 버튼(.has-value)
  • 파일 메뉴 액션은 data-action 값으로 분기만 해 두고 실제 다운로드는 // 다운로드 로직 추가 주석으로 개발팀에 넘김

예상 질문

왜 @import 대신 @use / @forward를 썼나요?
@import는 전역 공유라 변수 충돌과 중복 출력 문제가 있고 Dart Sass에서 지원 종료 예정입니다. @use는 파일마다 필요한 모듈만 가져오고, 모듈은 한 번만 로드됩니다.
Sass 변수가 있는데 왜 CSS 변수로 다시 만들었나요?
Sass 변수는 컴파일 후 사라지지만 CSS 변수는 브라우저에 남아서 개발 단 JS나 템플릿에서도 var(--hm-primary-50)로 쓸 수 있고, 나중에 테마를 바꿀 때도 유리합니다. map + @each로 자동 생성해 값은 한 곳에서만 관리합니다.
패널이 닫힐 때 visibility에 지연을 준 이유는?
display: none은 트랜지션이 안 되고, visibility를 바로 hidden으로 바꾸면 슬라이드가 끝나기 전에 사라집니다. 닫힐 때만 0.4s 지연을 줘서 애니메이션이 끝난 뒤 숨기고, 숨겨진 상태에서는 클릭과 스크린리더 접근도 막힙니다.
푸터 삭제 요청은 어떻게 반영했나요?
레이아웃 높이가 모두 --footer-height를 기준으로 계산돼 있어서 변수만 0으로 바꿨습니다. 다시 살릴 수도 있게 원래 값은 주석으로 남겼습니다.
디자이너가 아닌 개발자가 쓰기 좋게 하려고 한 것은?
data 속성으로 동작을 연결해 JS를 몰라도 속성만 맞추면 되게 했고, 상태 값을 주석에 적었고, 섹션 시작·끝 주석을 일관되게 달았습니다. 데이터로 바뀌는 값(면적 비율 등)만 인라인으로 남겨 개발 단에서 값을 넣을 자리를 분명히 했습니다.
모달을 여러 개 만들 때 구조를 어떻게 잡았나요?
overlay / content / header / body / footer / close를 공용 .modal에 두고, 화면별 차이는 .modal-calendar, .modal-width-set 같은 변형 클래스로만 덮어썼습니다. 열고 닫는 건 모두 .is-open 클래스 하나로 처리합니다.
