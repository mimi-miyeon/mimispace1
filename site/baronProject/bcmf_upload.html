스택 (알고 있어야 할 것)

  • React 19 + TypeScript + Vite 6. 라우터 없이 App.tsx에서 state로 화면 전환 (보고서 보기 ↔ 인라인 수정)
  • vite.config.ts: base: '/upload/'(하위 경로 배포), 개발 서버 프록시로 /upload/api·/upload/map_data를 운영 서버로 전달 → 로컬에서 프론트만 띄워도 실제 API 확인 가능
  • 경로는 import.meta.env.BASE_URL 기준으로 만듦 (appPath()) → 배포 경로가 바뀌어도 이미지·API 경로 유지
  • 라이브러리: react-datepicker(+ date-fns 한국어), lucide-react(아이콘), ol(OpenLayers 지도) + proj4(좌표 변환), dxf(도면)
  • 백엔드: Python FastAPI + PostgreSQL (HWP → XML → 파싱 → 위치 검증 → DB 적재). 프론트는 결과 조회·수정

React ↔ iframe 연동 구조

  • 보고서는 React 이전에 만든 public/phase0/daily-report-phase0.html을 <iframe>으로 띄움 (기존 화면 재사용)
  • React가 iframeRef.current.contentWindow로 iframe 안 함수(loadData(), renderWorkItems())를 직접 호출하고, 설정 모달의 호버 항목 on/off 상태를 iframe 문서의 체크박스에 동기화
  • 그래서 iframe 쪽 스타일은 React 번들과 별개로 컴파일되는 CSS를 써야 함 → 1번의 컴파일 경로 2개가 생긴 이유

본인이 손댄 JS

  • 툴팁 위치 판단: getBoundingClientRect()로 위·아래 남은 공간을 계산해서, 아래가 부족하고 위가 충분할 때만 위로 띄움 (기존: 아래가 조금만 부족해도 위로 → 위에서 잘림)
  • 직군 중복 합치기: 등장 횟수를 세고 처음 나온 순서를 유지해 현장대리인, 안전관리자(2)처럼 출력

예상 질문

Tailwind 프로토타입을 왜 SCSS로 바꿨나요?
회사 서비스들이 같은 SCSS 토큰(색·간격·버튼 크기)을 쓰고 있어서, 이 앱도 같은 디자인 시스템에 맞춰야 다른 서비스와 화면이 통일됩니다. Tailwind 클래스가 JSX에 길게 붙어 있으면 디자이너가 수정하기도 어렵고요. 그래서 진입 CSS를 SCSS로 바꾸고, 화면 단위로 클래스만 교체했습니다.
전환하면서 기능이 깨지지 않게 어떻게 했나요?
DOM 구조·이벤트·텍스트·속성은 그대로 두고 className만 바꾸는 원칙을 정했습니다. 일부 클래스는 JS가 querySelector나 closest로 찾는 연결 고리라서, 지우기 전에 코드 전체에서 검색해 스타일 전용인지 확인했습니다.
SCSS 컴파일 경로가 왜 두 개인가요?
React 화면은 Vite가 SCSS를 import해서 번들에 넣지만, 보고서는 public/ 아래 독립 HTML이 iframe으로 열리는 구조라 Vite 번들을 쓸 수 없습니다. 그래서 보고서용 SCSS만 sass CLI로 public/phase0에 따로 컴파일했습니다. 토큰은 같은 변수 파일을 공유합니다.
헤더 탭이 겹쳐 보이게 한 방법은?
탭 꼬리를 ::after로 붙이고, 왼쪽 탭이 오른쪽 탭 위로 오도록 @for로 순서에 따라 z-index를 내림차순 계산했습니다. 선택된 탭만 z-index를 가장 높게 주고 살짝 올려서 앞으로 튀어나와 보이게 했습니다.
로딩 모달 깜빡임에서 opacity 대신 background-color를 애니메이션한 이유는?
opacity를 쓰면 안쪽 이미지까지 같이 흐려집니다. 배경 원만 깜빡이고 아이콘은 선명하게 두려고 배경색만 바꿨고, 반투명 색은 color-mix()로 토큰 색에서 만들었습니다.
달력에서 날짜 두 개가 선택된 것처럼 보인 원인은?
react-datepicker는 실제 선택(--selected)과 키보드 포커스(--keyboard-selected)를 따로 표시하는데, 기본 스타일이 둘 다 배경색을 칠합니다. 키보드 포커스 스타일을 투명하게 바꾸고, "작업 있는 날 / 이전 달 / 선택됨" 상태가 겹칠 때 어떤 스타일이 이길지 선언 순서를 정리했습니다.
자동완성 때 인풋 배경이 바뀌는 문제는 어떻게 막았나요?
크롬은 자동완성된 인풋에 자체 배경을 강제로 칠하고 일반 CSS로는 덮이지 않습니다. :-webkit-autofill에 background-color transition을 아주 길게(9999s) 줘서 배경이 바뀌는 게 사실상 보이지 않게 했습니다.
AI 도구는 어떻게 썼나요?
애니메이션이나 툴팁처럼 초안이 필요한 부분에 쓰고, 커밋에 표시해 추적했습니다. 대신 "JS·구조·텍스트는 건드리지 않는다" 같은 규칙을 정해 두고, 결과는 직접 화면과 코드로 확인한 뒤 반영했습니다.

6경력기술서 문장 예시

  • 고속도로 사업단 일일작업보고 업로드·검토 웹앱(React + TypeScript + Vite)의 UI를 담당해, AI 프로토타입(Tailwind)을 사내 SCSS 디자인 시스템으로 전환했습니다. 팀 커밋의 약 70%(168건)를 맡았습니다.
  • React 번들(Vite)과 iframe으로 열리는 레거시 보고서 페이지(sass CLI)로 SCSS 컴파일 경로를 나눠, 하나의 디자인 토큰으로 두 화면의 스타일을 맞췄습니다.
  • HWP 업로드, 파싱 진행, DB 적재 완료, 위치 사전(Dictionary) 등 모달 10여 종을 공용 모달 구조로 퍼블리싱하고, 진행 상태를 알려주는 애니메이션을 적용했습니다.

  • JS 연결 클래스를 먼저 확인하고 className만 바꾸는 원칙으로, 기능 변경 없이 디자인만 교체했습니다.
